分组研讨 · 业态：货架电商

这条流水线上
我贴 5 个标签，不贴 1 个万能体

货架电商的智能体不该做成"懂一切的导购"，而该做成流水线上的 5 个工位： 每个工位只干一件事、只读一份数据、只交一份可核对的结果。
判断能不能贴标签，只看三条：成本是人力还是损耗、错了能不能被拦住、效果能不能落进已有报表。

Pipeline

七段流水线，五个工位被点亮

上游省库存，中游省工时，前端省人头，后端省损耗，末端守口碑——否则前面省的全从差评里漏掉。

灰色两段不是不能做，而是成本不在人力、错误不可拦、或数据不在自己手上——所以先不贴。

Landing Points

五个落点，每个都回答四问

四问的答案必须是"可核对的"：成本项要能对到报表科目，输入输出要能指到源单据，指标要能算出来。

01

选品参谋

选品备货
成本项：库存资金占用 + 缺货机会成本

痛点 / 对应成本

靠运营经验拍脑袋选品，两头亏：滞销压资金、爆款断货丢搜索权重。这是唯一一个"卖得好也亏、卖不好更亏"的成本，必须由数据管。

智能体完成什么任务

把"搜索词增长 + 类目价格带空档 + 自有 SKU 动销/退货/毛利"三张表对齐，输出上新候选、补货点、滞销处置路径。

输入站内搜索词榜、类目大盘与竞品价格带、SKU 销量/库存/退货率/毛利率、供应商起订量与交期。
输出候选清单（预测销量区间 + 理由 + 风险）、补货建议表、滞销处置单，每条带数据出处。
库存周转 62 天 → 48 天
新品 90 天成功率 18% → 26%
缺货率 7% → 3%
滞销库存占比 21% → 12%
周转天数降 14 天 = 释放资金 × 资金成本率，这是财务能直接签字的口径。
02

内容工厂

内容上架
成本项：内容生产人力 + 上新时滞

痛点 / 对应成本

一个 SKU 从拍照到详情上线要 3-5 天，多平台还要各改一遍文案与违禁词，新品永远错过第一波流量窗口。时滞不进报表，却是新品起不来的第一因。

智能体完成什么任务

用结构化参数和类目知识，产出标题（含关键词坑位）、五点卖点、详情结构、主图与短视频脚本，并跑违禁词/极限词校验。

输入SPU 参数表、类目词根表、平台违禁词库（版本化）、竞品差评与"问大家"、历史高转化详情模板。
输出多平台差异化文案包 + 违禁词校验报告 + 关键词覆盖评分；人审后发布，智能体不直发。
单 SKU 内容工时 4.5h → 0.5h
上新周期 5 天 → 1.5 天
7 日点击率（A/B）+8~15%
违禁词下架 → 0
工时省下是确定的，转化提升未必确定。所以先卖"工时 + 上新速度"，转化用分组 A/B 后置证明。
03

第一响应人

售前咨询
成本项：客服人力 + 未响应流失

痛点 / 对应成本

70% 咨询是重复的（尺码、材质、发货、优惠叠加），高峰排队、夜间无人应答直接流失；客服规模随大促波动，最不经济。

智能体完成什么任务

在详情页与客服首轮做"有据可查"的应答：参数、尺码搭配、时效、优惠叠加；超出范围立即转人工并带上下文。

输入商品参数与尺码表、实时库存接口、实时物流时效、活动规则库（含互斥逻辑）、优质人工会话 QA 对。
输出答案 + 引用出处（参数表 / 规则条款 / 接口返回）+ 置信度；越阈值自动转人工。
自助解决率 35% → 65%
首响时长 90s → 3s
咨询转化率 +2~4pt
人均接待量 1.8×
最容易翻车的标签：库存、价格、优惠、时效四类问题绝不能靠"模型记住"，必须走实时接口——这是答"错了谁负责"的设计前提。
04

判责员

履约售后
成本项：售后人力 + 退货运损 + 判责扣款

痛点 / 对应成本

退货审核靠人一张张看凭证图，纠纷判责慢、口径不一，仅退款被滥用，平台判责扣款和 DSR 下滑跟着来。

智能体完成什么任务

凭证核验（图文是否一致）、按平台与店铺规则给出判责结论 + 处置方案（补发/换货/退款/驳回）、生成安抚话术、异常件主动预警。

输入订单与物流轨迹、凭证图、售后规则库（版本化）、历史人工判责案例（金标）、客户退货频次与纠纷史。
输出结论 + 依据条款 + 建议方案 + 置信度；超额仅退款、疑似欺诈强制人工终审。
处理时长 26h → 4h
一次解决率 61% → 82%
改判率 ≤3%
退货物流成本 -10~20%
涉及资金与责任，只做"建议 + 依据"，不做终裁。这一条让讲师不会问"赔钱算谁的"。
05

口碑雷达

评价复购
成本项：口碑损失导致的转化下滑

痛点 / 对应成本

一条差评 T+2 才被发现，这几天它在影响所有访客；回复千篇一律；"问大家"无人答直接劝退。隐性但最大的成本。

智能体完成什么任务

差评实时归因（质量/物流/描述不符/尺码/客服）、生成合规回复、把高频问题回流成详情修改单与供应链预警、自动补答"问大家"。

输入评价与问大家原文、退货原因码、客服工单、商品参数。
输出归因日报（Top 问题 + 影响 GMV 估算）+ 回复草稿 + 详情修改建议单 + 供应链预警。
差评响应 48h → 2h
同类复发率 -40%
改后退货率 -1.5pt
问大家覆盖 40% → 95%
红线：只做自家店铺的合规回复与问题回流，不删评、不刷评、不干预评价真实性。否则数据链先烂。
Instructor Q1

数据从哪来？不说"我们有数据"，说"每条结论都能指回源单据"

按可信度分三层，每层用法不同——混在一起用，是所有智能体项目失败的第一原因。

层来源特征用法
L1 事实源 ERP / OMS / WMS / CRM：订单、库存、物流轨迹、售后工单、商品主数据 内部系统、有唯一单据号、可实时接口 只读实时查询，绝不喂给模型记忆
L2 规则源 平台规则、违禁词库、活动政策、售后判责规则 变化快、必须带版本 版本化管理 + 变更订阅，每次改动留 diff
L3 沉淀源 高转化详情页、优质人工会话 QA 对、历史判责案例与结果 最值钱，但要清洗标注 作范例库/检索库，人工判过的结果当金标集

数据契约

每个字段写清"谁提供、多久更新、为空怎么办"。库存/价格/物流标注为实时接口优先，超时降级转人工。

金标集

冷启动先做 500-1000 条人工标注测试集，任何版本上线前跑一遍，指标掉了不许发。

回流闭环

线上会话 → 人工纠正 → 进标注集 → 下版评测。没有回流的数据是一次性数据，不叫资产。

Instructor Q2

错了谁负责？责任在部署方，所以设计重点是"拦住、归因、兜住"

不承诺"模型不出错"，而是承诺"错误有上限、有留痕、能归因到数据错、规则错还是判断错"。

档位范围权限责任
只读建议 选品建议、文案草稿、口碑归因 智能体产出，人决策 决策人负责，智能体是助理
低风险自动 首轮问答、评价分类、物流异常预警 自动执行 + 兜底话术 + 一键转人工 商家负责，用 SLA 与赔付预算控损
高风险 退款金额、判责结论、价格与时效承诺 强制人工确认，智能体只出建议 + 依据 人工签字人负责

阈值闸

金额、置信度、客户等级任一越界必转人工。阈值写进配置，运营可改，不是埋在代码里。

留痕闸

输入、检索到的依据、输出、谁改的、改成什么，全链路可审计可回放。没有留痕的自动化不许上线。

兜底闸

按 GMV 千分之几计提错误赔付预算，配申诉流程。承认会错，比承诺不错更可信。

组织上要有一个岗：智能体运营（AI Ops），KPI 挂误判率与改判率，负责金标集、评测、badcase 周复盘。没有这个岗，上面三条都会退化成一纸文档。

Instructor Q3

客户为什么愿意付钱？为"报表上可验证的一个数字"，不为"智能体"

价值要翻译成财务语言，并且按"好不好证明"排序去卖，别按"技术好不好看"排序。

价值 01 · 最好卖

省人力

一个客服综合成本约 8k/月，自助解决率到 65% ≈ 少养 4-5 人；内容工时 4.5h→0.5h，月上 300 个 SKU 就是 1200 小时。

HR 能签字的口径。

价值 02 · 最容易被忽视

少损失

违禁词下架、判责扣款、DSR 掉流量、滞销清仓折价——老板心里有数但没人管的钱。守住"最低损失线"，价值立刻可见。

财务能签字的口径。

价值 03 · 最后卖

多赚钱

上新提速抢流量窗口、咨询转化 +2pt、退货率 -1.5pt。必须用同款 SKU 分组 A/B、控住价格与流量位来证明。

不能拿大盘同比糊弄。

先卖单点，不卖平台

只卖"售前问答"或只卖"内容工厂"，30 天出 A/B 结果再横向扩。一次卖五个落点，客户会怀疑你哪个都不精。

影子模式起步

前两周只建议不执行，先看它和人工判断的一致率（≥90% 才放权）。一致率是客户给权限的技术凭证。

定价锚点

按席位（替代几人）/ 按调用量 / 按 GMV 提升分成。B 端最认"省下的人头"和"确定的省钱"。

Boundary

我明确不贴的标签

讲边界比讲能力更能证明想清楚了——讲师通常在这停住。

不贴：自动定价改价

价格是商家命门，错误传导太快，收益归因也难。

不贴：纠纷终裁

涉及资金与法律责任，只能建议不能裁决。

不贴：评价干预 / 刷单

违规，且会直接毁掉整条数据链的可信度。
