0总览与流水线

一篇笔记进入切块链路，只经过三个函数：

raw.md
  │
  ├─ read_note()        → Note（title / tags / links / body）
  │
  ├─ build_sections()   → Section 树（按 # 标题层级）
  │
  └─ chunk_note()       → ChunkResult
        ├─ 每个 Section → 1 个 Parent
        └─ 每个 Section → N 个 Chunk（原子块打包）
阶段函数输入输出
解析read_note原始 MarkdownNote
分节build_sectionsNote.bodySection 树
切块chunk_noteNote + cfgParent[] + Chunk[]
向量化encode_documentsChunk.text[]np.ndarray
写库upsert_noteParent[] + Chunk[] + 向量LanceDB 两表

1Step 0 · read_note()：原始文件 → Note

输入

1-01.md 原文（约 1.5 万字）。特征：

  • 没有 frontmatter（开头不是 ---）
  • 没有行内 #tag
  • 没有 [[双链]]，目录用 [文字](#锚点)

处理

步骤函数发生了什么
拆 frontmatter_split_frontmatter无匹配 → meta={}，body_raw=raw
清洗clean_markdown[课程定位](#s1) → 课程定位；多空行压缩
取标题meta.get("title") or path.stem"1-01"（文件名去后缀）
合并标签fm_tags + inline_tags[]

输出 Note

字段值
note_id"1-01.md"
title"1-01" 不是正文 H1
frontmatter{}
tags[]
links[]
body清洗后全文
mtime / content_hash文件 mtime / sha1
要点 title 优先级 = frontmatter title → 文件名。正文里 # AI大模型应用开发培训 - 第1天... 是 H1，由 build_sections 单独处理，不进 title。

2Step 1 · build_sections()：Note.body → Section 树

规则

  1. FENCE_RE 维护 in_fence，代码块内 # 不当标题
  2. H1 若等于 root_title 且 root 无子节点 → 跳过
  3. 每个标题按层级挂到栈顶父节点，path = parent.path + [title]

输出树（简化）

root (path=["1-01"]) body=[开头行 + 目录长行] └─ H1 "AI大模型应用开发培训 - 第1天：环境搭建启动" ├─ H2 "课程定位" → s2 ├─ H2 "今日学习目标" → s3 ├─ H2 "今日主线任务" → s4 │ └─ H3 "课堂验收标准" → s5 ├─ H2 "第一部分：Python 多版本管理（约 50 分钟）" │ ├─ H3 "0. Python 简史（约 3 分钟）" │ ├─ H3 "1. 概念引入" │ ├─ H3 "2. 核心知识" │ ├─ H3 "3. 程序化示意" │ ├─ H3 "4. 示例演示" → s11（长节，7 chunk） │ └─ H3 "5. 小练习（5–10 分钟）" ├─ H2 "第二部分：虚拟环境与依赖管理（约 45 分钟）" │ ├─ H3 "1. 概念引入" │ ├─ H3 "2. 核心知识" │ ├─ H3 "3. 对比/规则说明" │ ├─ H3 "4. 扩展认识：venv、conda、uv、Poetry 到底怎么选" → s17（10–15 chunk） │ ├─ H3 "5. 示例演示" │ ├─ H3 "6. 常用国内镜像" │ └─ H3 "7. 小练习（5–10 分钟）" ├─ H2 "第三部分：PyCharm 安装与激活（约 40 分钟）" ├─ H2 "第四部分：解释器绑定与验证脚本（约 35 分钟）" ├─ H2 "第五部分：工程化目录规范（约 25 分钟）" ├─ H2 "课堂实操任务" ├─ H2 "常见问题与易错点" ├─ H2 "扩展阅读" → s52 └─ H2 "今日总结" → s54

深度优先遍历共约 55 个 section，sec_idx 按 DFS 顺序从 s0 递增。

注意 s0 是 root 本身，也会产出 Parent 和 Chunk；它只有开头行 + 目录，语义价值低，属于噪音块。

3Step 2 · chunk_note()：每个 Section 同时产出 Parent + Chunk

通用处理

raw_body   = "\n".join(section.body).strip()
heading_path = " > ".join(section.path)
prefix       = _breadcrumb(section.path, True)      # 相邻去重
parent_id    = f"{note_id}#s{sec_idx}"

parent_text  = f"{prefix}\n\n{raw_body}" if prefix else raw_body
if len(parent_text) > 2000:
    parent_text = parent_text[:2000].rstrip() + " …"

3.3 · s17「第二部分 4. 扩展认识」—— 超长节，10–15 个 chunk

body ≈ 5000+ 字，含 4 个对比表格。每个完整表格 → 1 个原子块（TABLE_RE 连续 | 行保持完整）。

表格通常 300–500 字，可能单独成 chunk，或与相邻段落拼。约产出 10–15 个 chunk，id = 1-01.md#s17c0 … #s17c12。Parent 截断到 2000 + …。

3.4 · s54「今日总结」—— 单个表格，1 个 chunk

body：一个 6 行 Markdown 表格。TABLE_RE 命中，整表一个原子块（约 500 字 < 900，不切）。Parent 约 550 字 < 2000，不截断。Chunk id = 1-01.md#s54c0。

3.5 · s0 root —— 「目录 chunk」，噪音块

body：开头行 + 清洗后的长串目录文字，两行无空行 → 一个普通段落原子块（800–1000 字）。

若 > 900 → split_long_text 按句切；目录无句号 → 硬切，step = 900-80 = 820，切成 2 片。pack_blocks → 1–2 个 chunk。

问题 这个 chunk 只有目录文字，语义价值低。当前代码不过滤，实际项目应加判断（如 if section is root and not section.body[1:]: continue）。

4Step 3 · 汇总 ChunkResult 与写库

项目估计值说明
parents 数量约 55每个非空 section 一个（含 root）
chunks 数量约 60–80短文 1 个/节；长文 7–15 个/节
截断的 Parents11 s17 s27 s32 s34 s38 s39 s47长节超 2000 字
tags_text全部 " "无标签

后续两条链路

ChunkResult
  ├─ encode_documents([c.text for c in chunks])  → 向量 (N, dim)
  └─ upsert_note(note_id, parents, chunks, vectors)
        ├─ chunks  表：id, vector, text, body, ..., parent_id, mtime
        └─ parents 表：id, text, note_id, note_title, heading_path, tags_text  （无 vector）
核心 子块有向量能检索，父块只做档案袋等回填。

5关键点速查

问题答案
title 从哪来frontmatter title → 文件名（path.stem），不是正文 H1
tags 从哪来frontmatter tags/tag + 正文 #tag，合并去重
双链 [[RAG|信息检索]]rag 进 Note.links，正文显示 信息检索
Parent 是什么一个 section 的完整正文 + 面包屑，超过 parent_max 截断
Chunk 是什么section 正文按原子块打包出的子块 + 面包屑
两者关系同时生成，Chunk.parent_id → Parent.id
原子块边界代码块 / 表格 / 引用 / 列表 保持完整；段落按空行切
什么时候真的"切"单原子块 > maximum 才 split_long_text
minimum 作用当前块 < minimum 时继续拼，哪怕超 target
向量化用哪个Chunk.text（面包屑 + 正文）
展示用哪个Chunk.body（纯正文）
父块回填靠什么parent_id 查 parents 表 → hit.parent_text
